> 本文保留为**设计记录**。实施后发现的额外问题见文末「实施后补记」。
>

**目标：** 把 pixiv 作为可切换的第二书源接进 my-mirror，与 manwaxu 并存。

**架构：** 复用第三档的「源注册表 + `src` 参数」骨架；pixiv 的差异（字段名、无章节、图片 host/防盗链）由**代理端的归一化层**吸收，**前端零改动**。

## 0. 探测结论（2026-10-04 实测，免登录）

| 端点 | 结果 |
|---|---|
| `GET /ranking.php?mode=daily&format=json&p=N` | ✅ `contents[]`，含 `illust_id/title/url/user_name/tags[]/illust_page_count/view_count` |
| `GET /ajax/search/artworks/{kw}?word=&p=&order=date_d&mode=all&type=all&s_mode=s_tag` | ✅ `body.illustManga.data[]` + `total` |
| `GET /ajax/illust/{id}` | ✅ `body`，含 `urls.original/tags.tags[]/userId/pageCount/illustComment` |
| `GET /ajax/illust/{id}/pages` | ✅ `body[]`，**每页精确 `urls.original`** |
| `GET /ajax/user/{uid}/profile/all` | ✅ `body.illusts{id:null}`（仅 id 列表） |
| `GET i.pximg.net/...` **无 Referer** | ❌ **403** |
| `GET i.pximg.net/...` 带 `Referer: https://www.pixiv.net/` | ✅ |

**三条关键结论：**

1. **全部免登录** —— 无需 cookie，代理直接可拉。
2. **`/pages` 给出每页精确 URL** —— 多页作品的扩展名每页可能不同（`.jpg`/`.png`），**不能靠 `_p0.jpg` 猜**，必须调 `/pages`。
3. **图片是防盗链不是加密** —— 只要带 Referer，`decrypt` 必须为 `false`，也不需要 CDN 容灾链。比 manwaxu 那套 AES 简单得多。

## 1. 核心难点：字段名完全不同

前端（`manga_reader.html`）现在硬编码 manwaxu 的字段名，`cardHtml` / `renderHome` / `renderSearch` / `openDetail` 都是直取。pixiv 一个都对不上：

| 前端要 | manwaxu | pixiv | 转换 |
|---|---|---|---|
| 列表键 | `comicList` / `list` | `contents[]` / `body.illustManga.data[]` | **包裹**成 `comicList` |
| `id` | `id` | `illust_id` / `id` | 改名 |
| `title` | `title` | `title` | 直取 |
| `pic`/`cover` | `pic` | `url` | 改名 |
| `author` | `author` | `user_name` / `userName` | 改名 |
| `tags`（**逗号串**） | 逗号串 | `tags[]`（**数组**） | `join(',')` |
| `tHits` | `tHits` | `view_count` | 改名 |
| `collection` | `collection` | — | 常量 |
| `status` | 数字 | — | 常量（1） |
| `intro` | `intro` | `illustComment`/`description` | 改名 |
| **章节** | `/chapters` 多话 | **pixiv 无章节** | **合成 1 话**，`picCount`=pageCount |
| **图片列表** | `data.images[]` | `/pages` → `body[].urls.original` | **包裹**成 `{images:[{url}]}` |

### 决策：映射层放**代理端**（前端零改动）

理由：
- 前端已 1683 行；再塞一套字段映射会更乱。
- 前端有 8 个 `apiGet` 调用点 + 全部渲染代码，动前端要改一片。
- **「描述怎么从源取数并归一化」正是「书源规则」的职责** —— 符合 `AGENTS.md` 的分层定义，不是把 UI 逻辑塞进代理。
- 代理端做映射 = 前端对第二个源**完全无感**，回归面最小。

源定义里新增 `adapt` 声明，proxy 取到上游 JSON 后按声明归一化：

```js
// SOURCES.pixiv
adapt: {
  listKey: 'contents',            // 列表数组在响应里的位置
  listWrap: 'comicList',          // 归一化后包成前端认的键名
  fields: { id:'illust_id', title:'title', pic:'url', author:'user_name',
            tags:'tags', hits:'view_count', intro:'description' },
  tagsJoin: true,                 // tags 数组 → 逗号串
  fakeChapters: true,             // 无章节源 → 合成单话
  imagesWrap: 'images'            // /pages 的 body[] → {images:[{url}]}
}
```

> **注意**：`/ajax/search` 的列表在 `body.illustManga.data`（两层），ranking 在 `contents`（一层）。`listKey` 需支持点号路径。

## 2. 图片规则必须按源独立

manwaxu 与 pixiv 的图片路径、host、防盗链方式**完全不同**：

| | manwaxu | pixiv |
|---|---|---|
| 路径前缀 | `/en_images/` | `/img-master/`、`/img-original/`、`/c/.../` |
| 实际 host | `tu.mhttu.cc` 等 CDN 链 | `i.pximg.net`（固定单 host） |
| 解密 | AES-256-CBC | **无** |
| 防盗链 | 需 `Referer: manwaxu.cc` | 需 `Referer: https://www.pixiv.net/` |
| 容灾 | 4 域名链 | 无（单 host） |

所以 `imageRule` 必须进源定义（第三档已如此设计），proxy 按**当前源**的规则匹配：

```js
// SOURCES.pixiv.imageRule
{ desc:'pixiv 图片', match:/^\/(img-master|img-original|c)\//,
  cdn:false, decrypt:false, host:'https://i.pximg.net' }
```

`toProxyPath()` 取 URL 的 `pathname` 作 `p`，正好落在 `match` 里 → 走 pixiv 图片分支。

## 3. 章节模型：pixiv 没有章节

前端 `openDetail` 后调 `/api/comic/{id}/chapters`，期望 `list[]`（`ch.id/title/sortId/picCount`）。

pixiv 一个作品就是一「话」。代理端 `fakeChapters` 时合成：

```js
// /api/comic/{id}/chapters 对 pixiv 源返回：
{ code:200, data:{ list:[ { id:'<illustId>', title:'<作品名>',
                          sortId:1, picCount:<pageCount>, isVip:false } ] } }
```

`picCount` 取自 detail 的 `pageCount`（或再调 `/pages` 拿 `body.length` 更准）。
`/api/comic/image/{cid}` 对 pixiv 源 = 调 `/ajax/illust/{cid}/pages` → 归一化成 `{images:[{url}]}`。

**副作用**：阅读器里「上一话/下一话」对 pixiv 无意义（永远只有 1 话）。需确认这是可接受的（或后续做「同作者/同系列」当章节，见待决策）。

## 4. 已发现的坑

| 坑 | 说明 | 处理 |
|---|---|---|
| **`is_masked: true`** | ranking 里有被屏蔽作品（R18/需登录），无 cookie 取图会失败 | 列表归一化时**过滤掉** `is_masked` |
| **`xRestrict`** | 0=全年龄 / 1=R18G / 2=R18 | 是否过滤由你定（见待决策） |
| **缩略图也要过代理** | `contents[].url` 也在 `i.pximg.net`，无 Referer 403 | `cardHtml` 已走 `toProxyPath()`，自动过代理 ✅ |
| **`illust_page_count` 是字符串** | ranking JSON 里是 `"3"` 不是 `3` | 归一化时 `Number()` |
| **`tags` 类型不一致** | ranking/search 是数组；detail 是 `tags.tags[].tag`（对象数组） | 两处分别处理 |
| **`/pages` 对 masked 作品可能失败** | 需登录 | 失败时回退用 `_p0` 拼 + 报错提示 |
| **Referer 与 Origin** | proxy 现在同时发 `Referer` 和 `Origin`（`BOOK_SOURCES.baseUrl`） | pixiv 需 `Referer: https://www.pixiv.net/`；`Origin` 可省或同值 |
| **UA** | 代理默认用 Chrome UA | 可沿用 |
| **无 `{id}` 占位时** | 现有 `rules.*.path` 用 `{id}`/`{cid}` 模板 | pixiv 的 `search` 路径要把关键词放**路径**里（`/ajax/search/artworks/{kw}`）而非 query | 需确认模板引擎支持 |

最后一条要重点确认：pixiv 搜索词在**路径段**里（`/ajax/search/artworks/初音`），而现有 `buildUrl` 是把 `params` 拼 query。`{keyword}` 若只当 query 参数传，pixiv 会忽略路径段。需要在 `rules.search` 支持路径占位符。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| **ToS / 合规** | pixiv 是画师平台，批量代理转发可能违反其条款。**这是你的决定**，我不重复提。 |
| 上游改版 | `adapt` 声明是配置不是代码，改字段名只改声明 |
| `/pages` 需登录（部分作品） | 过滤 `is_masked`；失败回退并提示 |
| 归一化层变重 | 映射是**数据驱动**（声明式），不是每源写一段代码 |
| 前端对「单话」体验困惑 | 阅读器的上下话按钮对 pixiv 无意义，需给提示或禁用 |
| 排序/分类语义不同 | manwaxu 的 `flag`/`type`（古风/玄幻/校园）pixiv 没有；pixiv 只有 ranking/search/tag |

## 实施后补记

### 1. `rules[x].path` 身兼前端与上游路径 → pixiv 首页/搜索/详情全 404

详见 `2026-10-04_2130-multi-source-switch.md` 的「实施后补记」。本文方案里
把 `path` 当作"上游路径模板"是对的，但**漏了一个前提**：前端也要用它当请求路径。
pixiv 的上游路径（`/ranking.php`、`/ajax/search/artworks/{keyword}`、
`/ajax/illust/{id}`）与前端路径（`/api/home`、`/api/search`、`/api/comic/{id}`）
完全不同，因此必须分离。修复后 pixiv 全部规则补了 `frontPath`。

### 2. 搜索端点字段名与 ranking 不同（已实测踩到）

`/ranking.php` 用 `illust_id` / `user_name` / `view_count`；
`/ajax/search/artworks` 用 `id` / `userName` / 无 `view_count`。
只声明一套 `adapt.field` 会让**搜索结果的 id 与 author 全空**，点进详情 404。
修复：新增 `adapt.searchField`，按端点覆盖字段映射。方案 §1 的表格里已列出
这层差异，但当时以为一套 `field` 就够 —— 实际必须按端点分。

### 3. 脏项过滤

线上搜索返回里确有 `title`/`pic` 全空的条目，归一化时一并过滤
（`!id && !title && !pic` 则丢弃）。

### 4. 真人浏览器验收

pixiv 全链路在真实 Chrome（影子 profile + CDP 真实鼠标）跑通：三栏 41/46/27
张卡片、缩略图与正文图真实解码（`i.pximg.net` 防盗链靠代理补 Referer）、
单话 UI 生效、上/下分区翻张正常。见 `2026-10-04_2130-multi-source-switch.md`。
